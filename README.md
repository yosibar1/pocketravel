# PocketRavel ✈️

**Find. Plan. Fly.** — a vacation-planning app: flight search & comparison, hotel search, ready-made vacation packages, and a smart (AI-powered) day-by-day trip planner.

Bilingual UI: **Hebrew (RTL)** and **English**, with a one-click language toggle.

> 🚧 Demo phase: flights, hotels and packages are served from realistic demo data behind an internal API layer, designed to be swapped for real providers (Amadeus, Booking, etc.) later.

## Features

- ✈️ **Flight search** — one-way / round-trip, sorting (price, duration, departure), filters (direct only, max price)
- 🏨 **Hotel search** — per destination and dates, sorting by rating/price, star filter, total-stay pricing
- 🎁 **Vacation packages** — flight + hotel bundles with highlights and inclusions
- 🪄 **Smart trip planner** — describe your trip (destination, days, budget, style, interests, free text) and get a day-by-day itinerary:
  - With `ANTHROPIC_API_KEY` set → personalized plans generated by Claude
  - Without it → a built-in rules engine over the destination data
- 🌍 **16 global destinations** with activities, tags and per-destination visuals
- 🔐 **Google sign-in** (NextAuth) — activates when OAuth credentials are configured; guest mode otherwise
- 🌐 **i18n** — full Hebrew/English dictionaries, automatic RTL/LTR switching

## Getting started

```bash
npm install
npm run dev
```

Open http://localhost:3000.

### Optional configuration

Copy `.env.example` to `.env.local` and fill in what you need:

| Variable | Enables |
| --- | --- |
| `ANTHROPIC_API_KEY` | AI-generated itineraries in the trip planner |
| `AUTH_GOOGLE_ID`, `AUTH_GOOGLE_SECRET`, `AUTH_SECRET` | Google sign-in |
| `TRAVELPAYOUTS_TOKEN` | Real flight prices in flight search (Travelpayouts/Aviasales data API) |

Everything works without any env vars (guest mode + rules-based planner).

## Architecture

```
src/
  lib/
    types.ts          # shared domain types
    i18n.ts           # he/en dictionaries
    visuals.ts        # per-destination gradient/emoji identity
    planner.ts        # rules-based itinerary engine (AI fallback)
    data/             # demo data layer (swap for real APIs later)
      destinations.ts
      flights.ts      # deterministic flight generator per route+date
      hotels.ts
      packages.ts
  app/
    api/
      flights/        # GET flight search
      hotels/         # GET hotel search
      plan/           # POST itinerary (Claude API → rules fallback)
      auth/           # NextAuth (Google)
    flights/  hotels/  packages/  packages/[id]/
    destinations/[id]/  planner/
  components/         # LanguageProvider, Header, SearchBox, cards…
```

The API routes are the seam for going live: replace the demo-data calls inside `api/flights` and `api/hotels` with real provider SDKs and the UI keeps working unchanged. The same API layer is intended to serve a future mobile app.
